➕ Mảng cộng dồn (Prefix Sum)

Kỹ thuật tính tổng đoạn con trong O(1) – dành cho học sinh đã biết mảng một chiều

1. Bài toán mở đầu2. Ý tưởng3. Công thức4. Cài đặt5. Chạy thử6. Bài tập7. Lưu ý

1. Bài toán mở đầu

Đề bài. Cho dãy n số nguyên a1, a2, …, an. Có q câu hỏi, mỗi câu cho hai số l, r (1 ≤ l ≤ r ≤ n). Hãy in ra tổng al + al+1 + … + ar.
Giới hạn: n, q ≤ 100 000.

Ví dụ: n = 8, dãy 3 1 4 1 5 9 2 6. Hỏi (3, 6) → 4 + 1 + 5 + 9 = 19.

Cách 1: duyệt trực tiếp

while (q--) {
    int l, r; cin >> l >> r;
    long long s = 0;
    for (int i = l; i <= r; i++) s += a[i];
    cout << s << "\n";
}

Đúng, nhưng chậm. Mỗi câu hỏi có thể phải cộng tới n số, tổng cộng khoảng n × q = 100 000 × 100 000 = 1010 phép cộng. Máy tính chỉ làm được khoảng 108 phép tính mỗi giây, nên chương trình sẽ chạy hàng phút và bị quá thời gian (TLE).

❓ Câu hỏi để suy nghĩ: các câu hỏi đều hỏi trên cùng một dãy số. Mỗi lần ta lại cộng lại từ đầu, có phải đang làm việc lặp đi lặp lại không? Có thể tính trước điều gì đó một lần để mọi câu hỏi sau đó trả lời thật nhanh?

2. Ý tưởng: tính trước tổng từ đầu dãy

Thay vì lưu tổng của từng đoạn (quá nhiều đoạn), ta chỉ lưu tổng của các đoạn bắt đầu từ đầu dãy. Gọi pre[i] là tổng của i số đầu tiên:

pre[0] = 0
pre[1] = a[1]
pre[2] = a[1] + a[2]
pre[3] = a[1] + a[2] + a[3]
...
pre[i] = a[1] + a[2] + ... + a[i]

Hai điều cần nhớ:

  • pre[0] = 0 (tổng của 0 số là 0). Quy ước này rất quan trọng, sẽ thấy ở mục sau.
  • Mỗi giá trị tính nhanh từ giá trị trước: pre[i] = pre[i-1] + a[i]. Vì thế cả mảng pre chỉ tốn n phép cộng.

Với dãy mẫu 3 1 4 1 5 9 2 6:

i012345678
a[i]–31415926
pre[i]0348914232531

Ví dụ pre[3] = pre[2] + a[3] = 4 + 4 = 8.

3. Công thức tính tổng đoạn [l, r]

S(l, r) = pre[r] − pre[l−1]

Vì sao đúng?

Xét đoạn [3, 6] của dãy mẫu:

i12345678
a[i]31415926
  • pre[6] = a1 + a2 + a3 + a4 + a5 + a6 → gồm phần cần tính và phần thừa ở đầu.
  • pre[2] = a1 + a2 → đúng bằng phần thừa đó.
  • Trừ đi, phần thừa biến mất: pre[6] − pre[2] = a3 + a4 + a5 + a6 = 23 − 4 = 19 ✔

Tại sao là l−1 mà không phải l? Vì ta cần giữ lại a[l]. Nếu trừ pre[l] thì a[l] cũng bị trừ mất. Phần cần bỏ là những số đứng trước l, tức là a[1..l-1].

Tại sao cần pre[0] = 0? Khi l = 1, công thức thành pre[r] − pre[0]. Nhờ pre[0] = 0, không cần viết riêng trường hợp đoạn bắt đầu từ đầu dãy.

4. Cài đặt trong C++

#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false); cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    vector<long long> pre(n + 1, 0);     // pre[0] = 0
    for (int i = 1; i <= n; i++) {        // đánh số từ 1
        long long x; cin >> x;
        pre[i] = pre[i - 1] + x;
    }
    while (q--) {
        int l, r; cin >> l >> r;
        cout << pre[r] - pre[l - 1] << "\n";
    }
}

Phân tích: dựng mảng pre mất O(n), mỗi câu hỏi mất O(1). Tổng O(n + q) ≈ 200 000 phép tính, so với 1010 của cách 1.

💡 Ta không cần lưu riêng mảng a, vì ta chỉ cần pre. Nếu sau này cần lại a[i] thì lấy pre[i] − pre[i−1].

6. Bài tập nâng dần

Mỗi bài đều dùng ý tưởng "tính trước một lần, dùng nhiều lần". Hãy tự nghĩ trước, rồi bấm Xem lời giải. Quy ước chung: mảng đánh số từ 1, dùng long long.

Bài 1. Tổng đoạn (cơ bản)

Cho n số và q truy vấn (l, r). In tổng đoạn cho mỗi truy vấn.

Xem lời giải

Chính là bài toán mở đầu: xây pre, trả lời mỗi truy vấn bằng pre[r] - pre[l-1]. Code ở mục 4.

Bài 2. Đếm số chẵn trong đoạn (dễ)

Cho n số và q truy vấn (l, r). Với mỗi truy vấn, đếm có bao nhiêu số chẵn trong a[l..r].
Ví dụ: dãy 3 4 6 7 8, truy vấn (2, 5) → 3.

Xem lời giải

Hướng dẫn: cộng dồn không chỉ dùng cho "giá trị" mà còn dùng cho "số lượng". Đặt c[i] = số lượng số chẵn trong a[1..i]. Mỗi số chẵn "đóng góp" 1, số lẻ đóng góp 0, nên c[i] = c[i-1] + (a[i] % 2 == 0). Số chẵn trong [l, r] là c[r] - c[l-1].

vector<int> c(n + 1, 0);
for (int i = 1; i <= n; i++) {
    int x; cin >> x;
    c[i] = c[i - 1] + (x % 2 == 0 ? 1 : 0);
}
while (q--) {
    int l, r; cin >> l >> r;
    cout << c[r] - c[l - 1] << "\n";
}

Cách này dùng được cho mọi điều kiện: đếm số dương, số chia hết cho 3, số bằng một giá trị cho trước, …

Bài 3. Vị trí cân bằng (trung bình)

Tìm vị trí i sao cho tổng các số bên trái i bằng tổng các số bên phải i (không tính a[i]). In vị trí nhỏ nhất, nếu không có in -1.
Ví dụ: dãy 1 3 5 2 2 → 3 (trái: 1+3 = 4, phải: 2+2 = 4).

Xem lời giải

Hướng dẫn: tổng bên trái i là pre[i-1]; tổng bên phải là pre[n] - pre[i]. Chỉ cần thử từng i và so sánh hai giá trị đó. Độ phức tạp O(n).

int ans = -1;
for (int i = 1; i <= n; i++) {
    long long trai = pre[i - 1];
    long long phai = pre[n] - pre[i];
    if (trai == phai) { ans = i; break; }
}
cout << ans;

Bài 4. Đoạn k phần tử liên tiếp có tổng lớn nhất (trung bình)

Cho n số và số k. Trong tất cả các đoạn gồm đúng k phần tử liên tiếp, tìm tổng lớn nhất.
Ví dụ: dãy 1 -2 3 4 -1 2, k = 3 → 6 (đoạn 3 4 -1).

Xem lời giải

Hướng dẫn: các đoạn dài k kết thúc tại i = k, k+1, …, n, bắt đầu tại i-k+1. Tổng của nó là pre[i] - pre[i-k]. Duyệt i và giữ giá trị lớn nhất. Đặt best ban đầu rất nhỏ vì tổng có thể âm.

long long best = LLONG_MIN;      // #include <climits>
for (int i = k; i <= n; i++)
    best = max(best, pre[i] - pre[i - k]);
cout << best;

Bài 5. Đoạn con liên tiếp có tổng lớn nhất (khá)

Cho n số (có thể âm). Chọn một đoạn liên tiếp không rỗng sao cho tổng lớn nhất. In tổng đó.
Ví dụ: dãy -2 1 -3 4 -1 2 1 -5 4 → 6 (đoạn 4 -1 2 1).

Xem lời giải

Hướng dẫn: tổng đoạn [l, r] là pre[r] - pre[l-1]. Cố định điểm kết thúc r; để tổng lớn nhất ta cần trừ đi pre[j] nhỏ nhất trong các j = 0 … r-1. Vậy khi duyệt r từ trái sang phải, ta giữ minPre = giá trị nhỏ nhất của pre ở các vị trí đứng trước r.

Thứ tự trong vòng lặp rất quan trọng: tính đáp án trước, cập nhật minPre sau, để đoạn luôn không rỗng.

long long best = LLONG_MIN, minPre = 0;   // minPre bắt đầu = pre[0]
for (int r = 1; r <= n; r++) {
    best   = max(best, pre[r] - minPre);
    minPre = min(minPre, pre[r]);
}
cout << best;

Độ phức tạp O(n). Đây là cách nhìn "tổng tiền tố" của bài toán nổi tiếng (thuật toán Kadane).

Bài 6. Đếm số đoạn có tổng bằng K (khó)

Cho n số (có thể âm) và số K. Đếm có bao nhiêu đoạn liên tiếp [l, r] có tổng đúng bằng K.
Ví dụ: dãy 1 2 1 2 1, K = 3 → 4 (các đoạn [1,2], [2,3], [3,4], [4,5]).

Xem lời giải

Hướng dẫn: đoạn [l, r] có tổng K khi pre[r] - pre[l-1] = K, tức pre[l-1] = pre[r] - K. Duyệt r từ trái sang phải, với mỗi r ta cần biết đã có bao nhiêu vị trí trước đó có pre bằng pre[r] - K. Dùng map để đếm số lần mỗi giá trị pre đã xuất hiện.

  • Bắt đầu với cnt[0] = 1 (ứng với pre[0] = 0).
  • Với mỗi r: cộng cnt[pre[r] - K] vào đáp án, sau đó mới thêm pre[r] vào cnt.
#include <map>
map<long long, int> cnt;
cnt[0] = 1;
long long s = 0, ans = 0;
for (int i = 1; i <= n; i++) {
    long long x; cin >> x;
    s += x;                          // s chính là pre[i]
    if (cnt.count(s - K)) ans += cnt[s - K];
    cnt[s]++;
}
cout << ans;

Độ phức tạp O(n log n). Bài này không cần lưu cả mảng pre, chỉ cần tổng đang chạy s.

7. Lưu ý và lỗi thường gặp

Quên pre[0] = 0 hoặc đánh số từ 0: dễ sai khi l = 1 (truy cập pre[-1]). Hãy đánh số từ 1 và chừa sẵn pre[0].
Nhầm pre[l] với pre[l-1]: nhớ rằng phải giữ lại a[l].
Tràn số: 105 số, mỗi số tới 109 cho tổng khoảng 1014, vượt int. Hãy dùng long long cho pre.
Mảng thay đổi: prefix sum chỉ hợp khi dãy không đổi giữa các truy vấn. Nếu có thao tác sửa giá trị xen kẽ thì cần cấu trúc khác (ví dụ Fenwick Tree).
Tóm tắt: tính pre[i] = pre[i-1] + a[i] một lần trong O(n), sau đó mỗi truy vấn tổng đoạn là pre[r] - pre[l-1] trong O(1).
