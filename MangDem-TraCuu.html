1. Bài toán xuyên suốt và bậc 1: mảng đếm

Bài toán xuyên suốt. Cho dãy n phần tử và q câu hỏi, mỗi câu cho một giá trị x: x xuất hiện bao nhiêu lần trong dãy? (n, q ≤ 105). Ta sẽ giữ nguyên đề nhưng thay đổi dần "phần tử có thể là gì", và xem mỗi lần cần cấu trúc nào.
BậcPhần tử là…Cấu trúc
1Số nguyên không âm, nhỏcnt[] (mảng đếm)
2Số nguyên có thể âm, khoảng hẹpcnt[x + OFFSET]
3Số nguyên rất lớn hoặc khoảng rộngmap
4Ký tự, chuỗicnt[26], map<string,…>
5Cần nhanh hơn, không cần thứ tựunordered_map (băm)

Bậc 1: giá trị nằm trong 0 … 106

Dùng giá trị làm chỉ số: ô cnt[v] ghi số lần v xuất hiện (như chuyên đề Sắp xếp).

const int M = 1000000;
vector<int> cnt(M + 1, 0);
for (int i = 0; i < n; i++) { int v; cin >> v; cnt[v]++; }
while (q--) { int x; cin >> x; cout << cnt[x] << "\n"; }

Tra cứu O(1), rất nhanh. Cái giá là bộ nhớ: M + 1 ô, bất kể dãy có bao nhiêu số. Điều kiện sống còn: giá trị phải dùng được làm chỉ số (nguyên, không âm, không quá lớn).

❓ Câu hỏi: nếu đề đổi thành "phần tử có thể là số âm" thì cnt[-5] có chạy được không?

2. Bậc 2: có số âm → dịch chỉ số (offset)

Giả sử phần tử và x nằm trong −106 … 106. Chỉ số âm không tồn tại, nhưng ta chỉ cần dịch toàn bộ giá trị lên cho không âm: ánh xạ v → v + OFFSET với OFFSET = 106. Giá trị −106 thành ô 0, giá trị 0 thành ô 106, giá trị 106 thành ô 2·106.

const int OFF = 1000000;
vector<int> cnt(2 * OFF + 1, 0);
for (int i = 0; i < n; i++) { int v; cin >> v; cnt[v + OFF]++; }
while (q--) {
    int x; cin >> x;
    if (x < -OFF || x > OFF) cout << 0 << "\n";   // ngoài phạm vi: chắc chắn 0
    else cout << cnt[x + OFF] << "\n";
}
💡 Vẫn là mảng đếm, chỉ thêm một phép cộng. Học sinh nên thấy: "số âm" không bắt buộc phải đổi cấu trúc, miễn là khoảng giá trị đủ hẹp để cấp phát mảng. Nhớ kiểm tra truy vấn ngoài phạm vi.

3. Bậc 3: giá trị rất lớn → map

Bây giờ phần tử nằm trong −109 … 109 (khoảng 2·109 giá trị). Mảng đếm cần 2·109 ô, tức vài GB: không thể. Nhưng dãy chỉ có tối đa n = 105 phần tử, tức nhiều nhất 105 giá trị khác nhau cần ghi nhớ. Ta chỉ cần cấu trúc chỉ lưu những giá trị đã xuất hiện: đó là map.

map<K, V> lưu các cặp (khóa → giá trị), sắp xếp theo khóa. Ở đây khóa là phần tử, giá trị là số lần xuất hiện.

#include <map>
map<long long, int> cnt;
for (int i = 0; i < n; i++) { long long v; cin >> v; cnt[v]++; }
while (q--) {
    long long x; cin >> x;
    auto it = cnt.find(x);                          // tra cứu, không làm thay đổi map
    cout << (it == cnt.end() ? 0 : it->second) << "\n";
}

Chạy thử với dãy -5 100000000 -5 7 -5: sau khi đọc, cnt = {−5: 3, 7: 1, 100000000: 1}. Hỏi -5 → 3; hỏi 8 → find không thấy → 0.

Cạm bẫy: m[k] tự tạo khóa k với giá trị 0 nếu chưa có. Dùng m[x] để "hỏi" sẽ vô tình thêm khóa mới (làm size() sai và tốn bộ nhớ). Khi chỉ muốn tra cứu hãy dùng find hoặc count.

Chi phí: mỗi thao tác O(log n) (map tổ chức khóa theo thứ tự, tìm kiếm giống nhị phân). Với n = 105 thì chỉ cỡ 17 bước mỗi lần: rất nhanh.

💡 Cách khác bạn đã biết: sắp xếp dãy rồi dùng upper_bound − lower_bound (chuyên đề Tìm kiếm nhị phân) cũng trả lời được bài này. Khác biệt: map cho phép thêm dữ liệu xen kẽ với việc hỏi, còn sắp xếp + nhị phân chỉ hợp khi dữ liệu cố định.

4. Bậc 4: ký tự và chuỗi

Ký tự: vẫn dùng được mảng đếm

Mỗi ký tự thực chất là một số nguyên (mã ASCII), nên có thể làm chỉ số. Với xâu chỉ gồm chữ cái thường, dùng 26 ô:

int cnt[26] = {};
for (char c : s) cnt[c - 'a']++;      // 'a' → 0, 'b' → 1, ..., 'z' → 25
// với ký tự bất kỳ: int cnt[256]; cnt[(unsigned char)c]++;

Chuỗi: không dùng được làm chỉ số

Nếu phần tử là từ (chuỗi) thì cnt["apple"] với mảng thông thường là vô nghĩa: chuỗi không phải một số nguyên nhỏ. Khi đó dùng map với khóa là string:

map<string, int> cnt;
string w;
for (int i = 0; i < n; i++) { cin >> w; cnt[w]++; }
while (q--) {
    cin >> w;
    auto it = cnt.find(w);
    cout << (it == cnt.end() ? 0 : it->second) << "\n";
}

Chuỗi tự so sánh theo thứ tự từ điển nên map vẫn sắp xếp được. Mỗi so sánh hai chuỗi tốn thời gian tỉ lệ với độ dài chuỗi, nên chi phí thực tế là O(độ dài · log n) mỗi thao tác.

❓ Câu hỏi dẫn sang bậc sau: mảng đếm tra cứu trong O(1) vì biết ngay ô cần đến. Có cách nào "biến một chuỗi thành một số" để cũng dùng như chỉ số mảng không?

5. Bậc 5: băm (hash) và unordered_map

Ý tưởng: dùng một hàm băm h(khóa) biến khóa bất kỳ thành một số trong [0, B), rồi dùng số đó làm chỉ số vào mảng gồm B ô, y hệt mảng đếm. Ví dụ đơn giản: băm chuỗi bằng tổng mã ký tự, rồi lấy dư khi chia cho B = 7:

KhóaTổng mã ASCIIh = tổng mod 7Ô
"ab"97 + 98 = 195195 mod 7 = 66
"c"9999 mod 7 = 11
"ba"98 + 97 = 195195 mod 7 = 66 (trùng với "ab")

Hai khóa khác nhau rơi vào cùng một ô gọi là va chạm. Cấu trúc băm xử lý bằng cách mỗi ô giữ một danh sách nhỏ các khóa đã rơi vào nó. Hàm băm tốt trải đều khóa ra các ô nên các danh sách ngắn, và tra cứu gần như đi thẳng đến đáp án.

C++ có sẵn: unordered_map và unordered_set, dùng y hệt map và set:

#include <unordered_map>
unordered_map<string, int> cnt;     // chỉ đổi tên kiểu, phần còn lại giữ nguyên
cnt[w]++;
auto it = cnt.find(w);

Lưu ý khi thi: unordered_map có thể bị làm chậm cố ý bằng dữ liệu xấu (rất nhiều va chạm). Với n ≤ 105, map với O(log n) đã quá nhanh và an toàn hơn. Chỉ chuyển sang unordered_map khi thật sự cần.

6. set: khi chỉ cần biết "có hay không"

Nhiều bài không cần đếm, chỉ hỏi "phần tử này đã gặp chưa?". Khi đó dùng set: tập hợp các giá trị không trùng nhau, tự sắp xếp.

#include <set>
set<long long> s;
s.insert(v);                          // thêm (thêm lần hai không có tác dụng)
if (s.count(x)) cout << "CO";     // kiểm tra có/không, O(log n)
cout << s.size();                     // số phần tử khác nhau
s.erase(x);                           // xóa
auto it = s.lower_bound(x);          // phần tử nhỏ nhất ≥ x (nếu it == s.end() là không có)

Duyệt set cho các phần tử theo thứ tự tăng dần. Có thể xem set là "nhị phân động": làm được việc của nhị phân (tìm phần tử ≥ x) nhưng vẫn cho thêm và xóa xen kẽ. Cần nhanh hơn và không cần thứ tự thì dùng unordered_set.

8. Bài tập nâng dần

Với mỗi bài hãy tự hỏi: "khóa là gì? Miền giá trị lớn cỡ nào? Cần đếm hay chỉ cần có/không?"

Bài 1. Đếm số phần tử khác nhau (cơ bản, set)

Cho n số nguyên (|ai| ≤ 109). In số giá trị khác nhau.
Ví dụ: 5 1 5 2 1 → 3

Xem lời giải

Hướng dẫn: bỏ tất cả vào set; set tự loại trùng, số phần tử của nó chính là đáp án. Giá trị lớn và có số âm nên không dùng mảng đếm.

set<long long> st;
for (int i = 0; i < n; i++) { long long x; cin >> x; st.insert(x); }
cout << st.size();

Bài 2. Tần suất các chữ cái (dễ, mảng đếm 26 ô)

Cho xâu s gồm chữ cái thường. In mỗi chữ cái xuất hiện trong s kèm số lần, theo thứ tự bảng chữ cái.
Ví dụ: banana → a 3, b 1, n 2 (mỗi cặp một dòng)

Xem lời giải

Hướng dẫn: chỉ 26 giá trị có thể, dùng ngay mảng đếm. Duyệt i từ 0 đến 25 sẽ tự ra theo thứ tự bảng chữ cái.

int cnt[26] = {};
for (char c : s) cnt[c - 'a']++;
for (int i = 0; i < 26; i++)
    if (cnt[i] > 0) cout << (char)('a' + i) << " " << cnt[i] << "\n";

Bài 3. Từ xuất hiện nhiều nhất (dễ, map với chuỗi)

Cho n từ (mỗi từ không có khoảng trắng). In từ xuất hiện nhiều nhất và số lần; nếu nhiều từ cùng nhiều nhất, in từ có thứ tự từ điển nhỏ nhất.
Ví dụ: to be or not to be to → to 3

Xem lời giải

Hướng dẫn: khóa là chuỗi nên dùng map<string,int>. map duyệt theo thứ tự từ điển, nên nếu dùng điều kiện so sánh nghiêm ngặt > thì từ nhỏ hơn được giữ lại khi bằng nhau.

map<string, int> cnt;
string w;
for (int i = 0; i < n; i++) { cin >> w; cnt[w]++; }
string bestW; int bestC = 0;
for (auto &p : cnt)
    if (p.second > bestC) { bestC = p.second; bestW = p.first; }
cout << bestW << " " << bestC;

Bài 4. Hai xâu có phải anagram không? (trung bình)

Cho hai xâu s và t gồm chữ cái thường. Hỏi t có phải là một cách sắp xếp lại các chữ cái của s không? In YES/NO.
Ví dụ: listen, silent → YES

Xem lời giải

Hướng dẫn: hai xâu là anagram khi mỗi chữ cái xuất hiện số lần bằng nhau. Đếm xâu s bằng cách cộng, xâu t bằng cách trừ; nếu mọi ô cuối cùng bằng 0 thì đúng. (Xâu khác độ dài thì chắc chắn sai.)

if (s.size() != t.size()) { cout << "NO"; return 0; }
int cnt[26] = {};
for (char c : s) cnt[c - 'a']++;
for (char c : t) cnt[c - 'a']--;
bool ok = true;
for (int i = 0; i < 26; i++) if (cnt[i] != 0) ok = false;
cout << (ok ? "YES" : "NO");

Cách khác: sắp xếp cả hai xâu rồi so sánh bằng nhau.

Bài 5. Đếm cặp có tổng bằng K (khá, tra cứu)

Cho n số nguyên (không sắp xếp, có thể âm hoặc lớn) và số K. Đếm số cặp i < j sao cho a[i] + a[j] = K.
Ví dụ: 1 5 3 3 3, K = 6 → 4 (cặp 1+5 và ba cặp 3+3)

Xem lời giải

Hướng dẫn: duyệt từng phần tử x từ trái sang phải. Số cặp kết thúc tại x bằng số lần giá trị K − x đã xuất hiện ở phía trước, đó chính là một lần tra cứu. Cộng vào đáp án, rồi mới ghi nhận x vào map.

map<long long, int> cnt;
long long ans = 0;
for (int i = 0; i < n; i++) {
    long long x; cin >> x;
    auto it = cnt.find(K - x);
    if (it != cnt.end()) ans += it->second;
    cnt[x]++;
}
cout << ans;

Thời gian O(n log n), không cần sắp xếp. So với hai con trỏ (cần dãy đã sắp xếp), cách này hoạt động trực tiếp trên dãy bất kỳ và đếm được cả các cặp trùng giá trị.

Bài 6. Đoạn dài nhất có tối đa k giá trị khác nhau (khó, hai con trỏ + map)

Cho n số nguyên (có thể lớn) và số k. Tìm độ dài lớn nhất của một đoạn liên tiếp chứa không quá k giá trị khác nhau.
Ví dụ: 1 2 1 2 3, k = 2 → 4 (đoạn 1 2 1 2)

Xem lời giải

Hướng dẫn: đây là cửa sổ co giãn (hai con trỏ cùng chiều) với thông tin theo dõi là tần suất các giá trị trong cửa sổ. Dùng map làm bảng đếm: số khóa của map (size()) chính là số giá trị khác nhau hiện có. Khi vượt quá k, thu hẹp bên trái; nhớ xóa khóa khi đếm về 0, nếu không size() sẽ sai.

map<long long, int> cnt;
int l = 0, best = 0;
for (int r = 0; r < n; r++) {
    cnt[a[r]]++;
    while ((int)cnt.size() > k) {
        if (--cnt[a[l]] == 0) cnt.erase(a[l]);
        l++;
    }
    best = max(best, r - l + 1);
}
cout << best;

Chạy thử: đến r = 3 cửa sổ 1 2 1 2 có 2 giá trị, độ dài 4. Ở r = 4 thêm 3 thì có 3 giá trị; bớt lần lượt 1, 2, 1 (khóa 1 về 0 nên bị xóa) cho đến khi còn đúng 2 giá trị; cửa sổ lúc đó là 2 3, độ dài 2. Đáp án 4 ✔ Độ phức tạp O(n log n).

9. Lưu ý và lỗi thường gặp

Dùng m[x] để hỏi: vô tình tạo khóa mới. Hãy dùng find hoặc count khi chỉ tra cứu.
Quên xóa khóa khi đếm về 0: size() không còn là số giá trị khác nhau hiện có (xem Bài 6).
Mảng đếm quá lớn hoặc chỉ số âm: kiểm tra miền giá trị trước khi chọn mảng đếm; nhớ kiểm tra truy vấn ngoài phạm vi khi dùng offset.
Mong đợi thứ tự từ unordered_map: duyệt cho thứ tự không xác định. Cần thứ tự thì dùng map.
Quá nhiều unordered_map trong bài có test xấu: có thể chậm; thử map khi nghi ngờ.
Tràn số: khóa và giá trị tổng có thể vượt int; dùng long long (kể cả biến đếm cặp, như Bài 5).
Tóm tắt: khóa dùng được làm chỉ số (nguyên, nhỏ) → mảng đếm (dịch chỉ số nếu có số âm). Khóa lớn, chuỗi, pair → map (có thứ tự, O(log n)) hoặc unordered_map (băm, trung bình O(1)). Chỉ cần "có/không" → set.
Chủ đề tiếp theo: mảng hai chiều và tổng tiền tố 2D (hoặc ngăn xếp, hàng đợi).
